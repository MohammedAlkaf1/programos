# ProgramOS · برنامج أو إس

منصة إدارة البرامج وقياس الأثر — متعددة المؤسسات (Multi-tenant)، ثنائية اللغة (عربي / English) مع دعم كامل لـ RTL.

## التشغيل من الصفر

افتح طرفيتين (Terminals) داخل VS Code:

**الطرفية الأولى — قاعدة البيانات (اتركها تعمل):**

```bash
npm install
npm run setup      # ينشئ ملف .env بكلمات مرور عشوائية
npm run db:start   # يشغّل PostgreSQL مدمجة على 127.0.0.1:55432
```

**الطرفية الثانية — التطبيق:**

```bash
npm run generate   # توليد Prisma Client
npm run db:push    # إنشاء الجداول
npm run db:seed    # خطط الاشتراك + بيانات تجريبية + حسابات الدخول
npm run dev        # http://127.0.0.1:3000
```

**الطرفية الثالثة (اختيارية) — عامل البريد:**

```bash
npm run mail:worker   # يفرّغ جدول Outbox كل 15 ثانية
```

بدون `SMTP_HOST` في `.env` تُكتب الرسائل في `data/mail/*.eml` بدل إرسالها،
فتستطيع فتح رابط التفعيل أو الدعوة محليًا دون خادم بريد.

ثم افتح <http://127.0.0.1:3000> — سيحوّلك تلقائيًا إلى `/ar`.

> **ملاحظة مهمة على Windows:** يُنشئ `db:start` قاعدة البيانات بترميز **UTF-8** إجباريًا.
> بدون ذلك يرث initdb ترميز النظام (WIN1252) ويفشل تخزين النص العربي.
> إن كانت لديك قاعدة قديمة بترميز مختلف فسيتوقف التشغيل مع حفظ البيانات، إلى أن تُنفذ عملية ترحيل صريحة.

## حسابات تجريبية

كلمة المرور للجميع: `Demo@12345`

| الدور | البريد | ما يراه |
|---|---|---|
| مدير النظام | `admin@programos.sa` | كل شيء + الفريق والصلاحيات + سجل التدقيق + تبديل المؤسسة |
| مدير برامج | `manager@programos.sa` | إنشاء البرامج، القرارات، الأنشطة، التقارير |
| منسق | `coordinator@programos.sa` | الأنشطة والحضور، فرز الطلبات |
| مُقيّم | `reviewer@programos.sa` | الطلبات المُسندة إليه فقط |
| أخصائي أثر | `impact@programos.sa` | المؤشرات، اعتماد القياسات، التقارير |
| مشاهد | `viewer@programos.sa` | تقارير مجمّعة فقط (بدون بيانات شخصية) |
| مستفيد | `beneficiary@programos.sa` | طلباته هو فقط، والتقديم على البرامج المفتوحة |

تظهر هذه الحسابات في شاشة الدخول فقط عندما يكون `DEMO_LOGIN=1` في `.env` (يضيفه `db:seed` تلقائيًا). احذف السطر قبل أي نشر حقيقي.

## دورة حياة الاشتراك

```bash
npm run billing:cycle              # تقدّم التجارب والتجديدات والتحصيل (شغّله يوميًا عبر cron)
npm run billing -- invoices        # الفواتير غير المسددة
npm run billing -- paid INV-2026-000001 REF-123   # تسجيل تحويل بنكي مستلم
npm run billing -- plans           # عرض الخطط
```

> **تسجيل السداد عملية مشغّل المنصة وليست عملية عميل** — لذلك هي في سطر الأوامر
> ولا تظهر في واجهة المؤسسة. لا يستطيع مدير المؤسسة تعليم فاتورته «مسددة».

المسار: تجربة 14 يومًا ← فاتورة عند انتهائها ← مهلة سداد 14 يومًا ← سماح 7 أيام
← تعليق مساحة العمل (بلا حذف أي بيانات) ← تُستعاد فورًا عند السداد.

### الدفع الإلكتروني عبر Moyasar

الدفع خلف واجهة `PaymentProvider` في [src/lib/billing.ts](src/lib/billing.ts). المنفَّذ منها اثنان:

| المزود | الاستخدام |
|---|---|
| `manual` | تحويل بنكي برقم مرجعي، ويسجّل مشغّل المنصة السداد من سطر الأوامر |
| `moyasar` | مدى وفيزا وماستركارد وآبل باي عبر صفحة دفع مستضافة لدى Moyasar |

لتفعيل Moyasar:

1. أنشئ حسابًا في [moyasar.com](https://moyasar.com) واستخرج المفتاح السري (يبدأ بـ `sk_test_` للاختبار و`sk_live_` للتشغيل).
2. اضبط في البيئة: `BILLING_PROVIDER=moyasar` و`MOYASAR_SECRET_KEY=sk_...`.
3. اختياري لكن موصى به: أنشئ Webhook في لوحة Moyasar يشير إلى `https://<النطاق>/api/hooks/moyasar` مع secret token، وضعه في `MOYASAR_WEBHOOK_SECRET`.

المسار: زر «سداد» في صفحة الاشتراك ينشئ فاتورة لدى Moyasar ويحوّل العميل إلى صفحة الدفع. عند العودة إلى `/ar/billing?payment=<invoice>` يستعلم التطبيق عن الفاتورة من Moyasar مباشرة ويسجّل السداد إن تم، فلا يعتمد التفعيل على وصول الـ Webhook. الـ Webhook، إن وصل لاحقًا، يجد العملية مسجلة ولا يغيّر شيئًا. في الحالتين يجب أن يطابق المبلغ الفاتورة إلى الهللة، وإلا سُجّل التعارض لمراجعة بشرية دون تفعيل.

الفواتير الصادرة قبل ضبط المزود تبقى على `manual` وتُسدَّد بالتحويل.

لإضافة مزود آخر (Tap، Stripe): نفّذ `createCheckout` و`parseEvent` ثم `registerProvider`، واضبط `BILLING_PROVIDER`. لا يتغير شيء آخر في التطبيق.

### الباقات والأسعار

قائمة الأسعار في [scripts/plans.ts](scripts/plans.ts). بعد تعديلها شغّل `npm run plans:sync` ليحدّث قاعدة البيانات في مكانها: الاشتراكات القائمة تبقى مرتبطة بالباقة نفسها وترى السعر الجديد عند الفاتورة التالية، والباقة المحذوفة من القائمة تُعطَّل ولا تُحذف.

```bash
npm run verify          # typecheck + vitest + build
npm run check:mvp       # رحلة القبول الكاملة من المتصفح: AC-01 إلى AC-12 (يتطلب تشغيل الخادم وقاعدة البيانات)
npm run check:phase2    # التكاملات والاستيراد والمساعد من طرف إلى طرف (يشغّل مستقبِلًا محليًا للتحقق من التوقيع)
```

ينشئ `check:mvp` مساحة عمل معزولة في كل تشغيل ويحتفظ بها للمراجعة، ويطبع بيانات الدخول في النهاية.
يغطي: التقديم برقم مرجعي وسجل موافقة، 20 محاولة قبول متزامنة على مقعد واحد، إعادة الإرسال بمفتاح التكرار،
الاستكمال على مستوى الحقول، تصدير الملفات كوظائف برابط منتهي الصلاحية، طلبات الخصوصية الخمسة، قائمة الإتلاف،
عزل الجهات، 24 مسارًا بالعربية والإنجليزية على 360px، والوصول المؤقت للدعم.

## المهام الخلفية

| الأمر | التكرار | ماذا يفعل |
|---|---|---|
| `npm run mail:worker` | خدمة دائمة | يفرّغ Outbox مع إعادة المحاولة بعد 1 و5 و30 دقيقة ثم يعلّم الرسالة Failed لتظهر في «رسائل تعذر إرسالها» لدى مدير النظام |
| `npm run reminders` | كل ساعة | تذكيرات 24 ساعة للمهل والأنشطة، وتنبيه المدير قبل 3 أيام من مهلة طلب الخصوصية |
| `npm run housekeeping` | مرة يوميًا | إغلاق التسجيل المنتهي، إتلاف المسودات القديمة، إنهاء الوصول المؤقت، حذف ملفات التصدير المنتهية، وتوليد قائمة الإتلاف حسب سياسة الاحتفاظ (اعتماد المدير مطلوب) |
| `npm run scan:files` | كل دقيقة | فحص المرفقات المعلقة عبر ClamAV (`CLAMAV_HOST` و`CLAMAV_PORT`) |
| `npm run integrations:worker` | خدمة دائمة | إرسال إشعارات الأحداث وحمولات الموصلات مع إعادة المحاولة ثم الإيقاف عند نفادها |
| `npm run billing:cycle` | مرة يوميًا | التجارب والتجديدات والتحصيل |

بدون `CLAMAV_HOST` تبقى المرفقات في الإنتاج بحالة Pending حتى يعمل الفحص، ولا يمكن تقديم طلب بمرفق معلق.
في التطوير تُقبل الملفات التي اجتازت فحص النوع مباشرة. اضبط `FILE_SCAN_BYPASS=1` فقط إذا أردت السلوك نفسه في بيئة أخرى وعلى مسؤوليتك.

## وحدة تحكم مشغّل المنصة

إنشاء الجهات وتعليقها وإغلاقها وتصدير بياناتها عمليات مشغّل وليست عمليات عميل، لذلك تعيش في سطر الأوامر:

```bash
npm run operator -- list
npm run operator -- create <slug> "<الاسم بالعربية>" "<English name>" admin@example.org "اسم المدير"
npm run operator -- suspend <slug> "السبب"      # قراءة وتصدير فقط
npm run operator -- resume <slug> "السبب"
npm run operator -- close <slug> 30 "السبب"      # Closing لمدة 30 يومًا ثم يسمح بالإتلاف
npm run operator -- export <slug> exports        # CSV لكل الوحدات + سجل التدقيق
npm run operator -- purge <slug>                 # بعد انتهاء مهلة الإغلاق فقط؛ يبقى سجل التدقيق وشواهد الإتلاف
```

الوصول المؤقت للدعم (Break glass) يمنحه مدير الجهة من صفحة الفريق لمشغّل محدد ولمدة محددة، وينتهي تلقائيًا.

## عقد الـ API

- كل كتابة `POST /api/command` بجسم `{action, data}`. أضف الترويسة `Idempotency-Key` (8 إلى 128 حرفًا) لتُعاد النتيجة نفسها عند التكرار دون تنفيذ ثانٍ.
- كل استجابة تحمل `x-correlation-id` ويُحفظ المعرف نفسه في سجل التدقيق. أرسل `x-request-id` لتستخدم معرفك.
- حد الاستخدام العادل 240 أمرًا في الدقيقة لكل مستخدم (429 عند التجاوز).
- التصدير: `export.request` ينتج الملف ويعيد `href` صالحًا 15 دقيقة؛ التنزيل من `GET /api/export?job=` يعيد التحقق من الصلاحية والملكية.
- جلسات العاملين تنتهي بعد 30 دقيقة خمول أو 12 ساعة، والتحقق بخطوتين إلزامي لهم.

## الموقع العام

الصفحات المفتوحة للزوار بلا تسجيل دخول:

| المسار | الصفحة |
|---|---|
| `/ar` و`/en` | الصفحة الرئيسية. يُعاد كتابة المسار داخليًا إلى `welcome` للزائر، ويبقى العنوان القصير كما هو |
| `/ar/welcome` | الصفحة الرئيسية بعنوانها الصريح |
| `/ar/pricing` | الأسعار، تُقرأ من جدول الباقات نفسه الذي تفرضه وحدة الاشتراك |
| `/ar/contact` | نموذج التواصل |
| `/ar/terms` | شروط الاستخدام |
| `/ar/privacy-policy` | سياسة الخصوصية |

الزائر الذي لا يحمل جلسة يرى الصفحة الرئيسية على `/ar`، ومن يحمل جلسة يرى لوحة المعلومات على العنوان نفسه.
الفحص في `src/proxy.ts` فحص وجود لا فحص ثقة: الصفحات والأوامر خلفه تتحقق من المستخدم الحقيقي من قاعدة البيانات.

هيدر الموقع يحمل مبدّل اللغة ومبدّل الوضع الفاتح والداكن، وهما المكوّنان نفسهما اللذان يستخدمهما التطبيق
([theme-toggle.tsx](src/components/shell/theme-toggle.tsx))، فما يختاره الزائر يبقى معه بعد تسجيل الدخول.
الاختيار يُحفظ في ملف ارتباط ويقرؤه الخادم، فتظهر الألوان الصحيحة من أول بايت دون وميض.

نصوص الموقع كلها في [src/i18n/site.ts](src/i18n/site.ts) بالعربية والإنجليزية، منفصلة عن قاموس المنتج
لأن الاثنين يتغيران لأسباب مختلفة. تعديل الوثائق النظامية يستلزم تحديث `LEGAL_UPDATED` في الملف نفسه.

نموذج التواصل يمر على `/api/public` مثل بقية العمليات بلا جلسة: ثلاث رسائل في الساعة لكل زائر،
وموافقة صريحة شرط للإرسال، وتُحفظ الرسالة في `ContactLead` ويصل إشعار إلى `CONTACT_EMAIL` ونسخة إلى المرسل.

`robots.txt` و`sitemap.xml` يفتحان الصفحات العامة فقط ويغلقان التطبيق. ضع `APP_URL` الصحيح قبل النشر
لأن العنوان الأساسي والروابط البديلة بين اللغتين تُبنى منه.

## التكاملات والواجهة البرمجية

### الواجهة البرمجية العامة

```
GET  /api/v1/openapi.json            وصف كامل للمسارات والصلاحيات
GET  /api/v1/programs                GET /api/v1/applications?programId=&status=
GET  /api/v1/beneficiaries           GET /api/v1/indicators?programId=
GET  /api/v1/reports/kpis            GET /api/v1/events?type=&cursor=
POST /api/v1/applications/review     POST /api/v1/applications/decide
POST /api/v1/applications/request-info
POST /api/v1/attendance              POST /api/v1/measurements
POST /api/v1/measurements/verify     POST /api/v1/indicators
```

المصادقة `Authorization: Bearer pos_...`. يُصدر المفتاح من صفحة التكاملات ويظهر مرة واحدة فقط،
ويُحفظ منه التجزئة لا النص. لكل مفتاح صلاحيات محددة، ويعمل بأقل دور يغطيها، فلا يتجاوز أبدًا ما تسمح به الشاشات.
الحد العادل 600 طلب في الدقيقة لكل مفتاح. أضف `Idempotency-Key` في عمليات الكتابة لتُعاد النتيجة نفسها عند التكرار.
إلغاء المفتاح أو تدويره يوقف القديم فورًا.

### إشعارات الأحداث

أضف وجهة من صفحة التكاملات واشترك بما يعنيك (`program.*` أو حدثًا محددًا). كل طلب يحمل:

```
x-programos-signature: t=<unix>,v1=<hmac-sha256 لِ "t.body">
x-programos-event: application.decided
x-programos-delivery: <معرّف المحاولة>
```

تحقق بحساب البصمة نفسها على السر الذي ظهر لك عند الإنشاء. الوقت داخل النص الموقَّع، فأي طلب مُلتقَط
يصبح بلا قيمة بعد خمس دقائق. المحاولات 1 و5 و15 و60 و180 و360 دقيقة ثم يتوقف الإرسال ويظهر في «إرسال متوقف»
لإعادة المحاولة بعد معالجة السبب. الحمولة تحمل معرفات وحالات فقط: لا إجابات نماذج ولا ملاحظات.

### الموصلات والتقويم

موصل واحد لكل نظام خارجي (تقويم، نظام تعلم، إدارة علاقات، تحليلات) بخريطة حقول ونطاق أحداث وسر خاص.
الحقول غير المذكورة في الخريطة لا تُرسل. تعطُّل المزود يبقى داخل طابور إعادة المحاولة ولا يوقف تشغيل أي برنامج.
لكل برنامج رابط تقويم مشتق من سر الموصل، يعمل في أي تطبيق تقويم ويحمل المواعيد والأماكن دون أي مشارك.
إيقاف الموصل يبطل كل روابطه.

### الإشعارات الواردة من المزودين

```
POST /api/hooks/billing      إشعارات الدفع (BILLING_WEBHOOK_SECRET)
POST /api/hooks/messaging    تقارير تسليم الرسائل (MESSAGING_WEBHOOK_SECRET)
```

التوقيع نفسه والنافذة الزمنية نفسها. المعالجة مطابقة لا زيادة: مبلغ لا يطابق الفاتورة لا يسددها،
وإعادة إرسال الإشعار نفسه لا تغيّر شيئًا لأن الزوج (المزود، المعرّف الخارجي) فريد.

### الدخول الموحّد

OIDC لكل جهة. لا تُقبل هوية إلا ببريد يؤكد المزود توثيقه وعلى نطاق مصرح به، فلا يمكن الاستيلاء على حساب
ببريد مُدخل يدويًا. إيقاف الربط يبطل كل الارتباطات القائمة ويُنهي جلساتها. رابط الدخول للمؤسسة يظهر في صفحة التكاملات.

### قنوات الرسائل

الرسائل القصيرة وواتساب عبر واجهة مزود. بلا موافقة مسجلة لا تُنشأ رسالة أصلًا، ولا يُرسل إلا قالب معتمد،
فيبقى اعتماد المزود للقوالب صحيحًا. يمنح الشخص موافقته بنفسه ويستطيع المدير سحبها فقط.
بدون `MESSAGING_PROVIDER` تُكتب الرسائل في `data/messages/` بدل إرسالها.

### الاستيراد من CSV

مرحلتان: معاينة تعرض ما سيحدث لكل سطر مع سبب كل رفض، ثم تنفيذ يعيد التحقق نفسه على البيانات الحية.
السطر الخاطئ لا يمنع بقية الملف. لا تُنشأ حسابات ولا تُرسل دعوات إلا باختيار صريح لكل منهما.
يُعامَل ما يبدأ بعلامة يساوي أو زائد أو @ كنص لا كصيغة.

## المساعد

معطّل افتراضيًا. يفعّله مدير النظام بعد الإقرار بطريقة المعالجة، ويحدد سقف إنفاق شهري ومدة احتفاظ بالمخرجات.

| الميزة | ما تفعله | الضابط |
|---|---|---|
| مسودة برنامج | وصف مقترح ومؤشرات أولية | مسودة لا تُستخدم قبل اعتماد شخص مسؤول |
| ملخص النتائج | فقرات تلخص أداء البرنامج | كل رقم يجب أن يطابق قياسًا محسوبًا في النظام، وإلا رُفض الملخص كاملًا |
| بحث في المستندات | إجابة من مستندات الجهة مع إحالة | الاسترجاع مقيّد بالجهة قبل تكوين الطلب، ونصوص المستندات محتوى لا تعليمات |

المتغيرات: `ANTHROPIC_API_KEY` للتشغيل الفعلي، و`AI_PROVIDER=stub` لمزود محلي حتمي يُستخدم في التطوير
والاختبار فقط ويُرفض في الإنتاج. التكلفة تُحسب بالهللات من عدد الوحدات وتُخصم من السقف، وعند بلوغه يتوقف المساعد
وحده دون أن يتأثر أي جزء آخر.

**المساعد لا يقرر.** لا يملك أدوات تنفيذ ولا مسار كتابة إلى الطلبات أو القرارات أو الأهلية،
ومخرجه يبقى مسودة حتى يعتمدها شخص باسمه. هذا مطبق في البنية لا في نص التعليمات.

## الترحيلات

`prisma/migrations/0_init` هو خط الأساس. للتطوير المحلي يكفي `npm run db:push`؛ للإنتاج استخدم `npx prisma migrate deploy`.

### قرارات تصميم تستحق المعرفة

- **أمر واحد للكتابة:** كل تعديل يمر عبر `POST /api/command` ثم `commands.ts`،
  فالتحقق والصلاحيات وسجل التدقيق في مكان واحد لا يمكن تجاوزه من الواجهة.
- **قراءة واحدة للعرض:** `getState()` تُنفَّذ مرة واحدة لكل طلب (عبر `cache()`)،
  ويشترك فيها الـ layout والصفحة معًا، وتُخفي الحقول الشخصية حسب الدور.
- **الألوان في الرسوم:** المقدار يُرسم بلون نحاسي واحد فقط (الطول هو الترميز)،
  والتغيّر في الأثر يستخدم لونين متقابلين **مع سهم ورقم بإشارة دائمًا** —
  لأن الأخضر/الأحمر لا يتجاوزان عتبة التمييز لعمى الألوان بمفردهما.
- **الوضع الداكن:** درجاته محسوبة على الخلفية الداكنة وليست قلبًا آليًا للفاتح،
  ويُحسم على الخادم من كوكي فلا وميض عند التحميل.
- **حدود الخطة تُفرض في طبقة الأوامر** لا في الواجهة، فتجاوزها عبر الـAPI مباشرة
  يُرفض بـ402. الواجهة تستخدم الأرقام نفسها لتعطيل الأزرار مبكرًا فقط.
- **المبالغ أعداد صحيحة بالهللات** لا أرقام عشرية، فلا تنحرف المجاميع.
- **أرقام الفواتير تُشتق من أعلى رقم صادر** لا من عدد الصفوف: العد ينكسر فور
  حذف أو إلغاء فاتورة فيتكرر رقم مستخدم.

## النشر

المشروع يُبنى صورتين من `Dockerfile` واحد: `app` للتطبيق (مخرجات `standalone` بلا مصدر ولا حزم تطوير)
و`worker` للمهام الخلفية والترحيلات ووحدة المشغّل. ملف `docker-compose.yml` يشغّل الحزمة كاملة على خادم واحد.

### التشغيل على خادم بـ Docker Compose

```bash
cp .env.example .env          # واملأ القيم المعلّمة (مطلوب)
docker compose up -d --build  # قاعدة البيانات، الترحيلات، التطبيق، العمال، المجدول
docker compose logs -f app
curl -s http://127.0.0.1:3000/api/health   # {"status":"ok"}
```

ما يحدث عند التشغيل بالترتيب:

1. `db`: PostgreSQL 17 بترميز UTF-8 على وحدة تخزين دائمة.
2. `migrate`: يعمل مرة واحدة، ينفّذ `prisma migrate deploy` ثم `plans:sync`، ثم يتوقف. لا يبدأ التطبيق قبل نجاحه.
3. `app`: التطبيق على المنفذ `APP_PORT` (الافتراضي 3000) خلف وكيل عكسي من اختيارك (Nginx أو Caddy) يتولى شهادة TLS.
4. `mail-worker` و`integrations-worker`: خدمتان دائمتان.
5. `scheduler`: يشغّل فحص المرفقات كل دقيقة، والتذكيرات كل ساعة، والإتلاف ودورة الفوترة يوميًا. لا حاجة لـ cron على المضيف.
6. `clamav` (اختياري): `docker compose --profile scan up -d` مع `CLAMAV_HOST=clamav` في `.env`. بدونه تبقى المرفقات معلقة في الإنتاج بحكم التصميم.

يحتاج خادم البناء اتصالاً بالإنترنت لأن الخط يُحمّل من Google Fonts وقت البناء.

أول مدير للمنصة بعد النشر:

```bash
docker compose run --rm scheduler npm run operator -- create <slug> "<الاسم بالعربية>" "<English name>" admin@example.org "اسم المدير"
```

### متغيرات البيئة

كل المتغيرات موثقة في `.env.example` مع علامة (مطلوب) على ما لا يعمل النظام بدونه:

| المجموعة | المتغيرات |
|---|---|
| الأساس | `POSTGRES_PASSWORD`, `AUTH_SECRET`, `APP_URL`, `AUTH_URL`, `CONTACT_EMAIL` |
| البريد | `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` |
| الدفع | `BILLING_PROVIDER=moyasar` مع `MOYASAR_SECRET_KEY` و`MOYASAR_WEBHOOK_SECRET`، أو `BILLING_WEBHOOK_SECRET` لمزود آخر |
| المرفقات | `CLAMAV_HOST`, `CLAMAV_PORT` |
| الرسائل | `MESSAGING_PROVIDER`, `MESSAGING_WEBHOOK_SECRET` |
| المساعد | `ANTHROPIC_API_KEY` |

لا تضع في الإنتاج `DEMO_LOGIN` ولا `AI_PROVIDER` ولا `LOCAL_DATABASE_PASSWORD`. التطبيق يرفض المزود التجريبي للمساعد
ويغلق مسار رمز التحقق التجريبي عندما يكون `NODE_ENV=production`، لكن الأصل ألا تكون القيم موجودة أصلًا.

### التشغيل بلا Docker

```bash
npm ci
npx prisma generate
npm run build
npm run db:migrate           # prisma migrate deploy
npm run plans:sync
HOSTNAME=0.0.0.0 PORT=3000 node .next/standalone/server.js
```

وشغّل بجانبه كخدمات دائمة (systemd أو ما يعادله): `npm run mail:worker` و`npm run integrations:worker` و`npm run scheduler`.
إن أردت cron بدل المجدول:

| المهمة | التكرار |
|---|---|
| `npm run scan:files` | كل دقيقة |
| `npm run reminders` | كل ساعة |
| `npm run housekeeping` | مرة يوميًا |
| `npm run billing:cycle` | مرة يوميًا |

### فحص الصحة

`GET /api/health` يعيد `{"status":"ok"}` عندما تستجيب قاعدة البيانات، و503 عندما لا تستجيب. لا يكشف نسخة ولا بيانات.
صورة `app` تستخدمه في `HEALTHCHECK` وتعتمد عليه منصات التشغيل لإعادة التشغيل.

### قبل أول عميل حقيقي

1. نطاق باسم المنتج وشهادة TLS على الوكيل العكسي، وقيمة `APP_URL` و`AUTH_URL` عليه.
2. مزود بريد يعمل، وتجربة رسالة تفعيل حقيقية.
3. نسخة احتياطية مجدولة لوحدة `db-data` وتمرين استعادة واحد على الأقل.
4. مراجعة نظامية لشروط الاستخدام وسياسة الخصوصية.
5. اعتماد قوالب الرسائل لدى مزود واتساب إن استُخدمت القناة.
